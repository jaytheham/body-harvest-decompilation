# Narrow allocator result and unsigned flag grouping

Matched `func_8007A198_89148` in `src.us/overlay_gameplay/outside/884C0.c` with IDO 5.3 -O2.

A named `s32` flag temporary displaced the compiler-generated byte argument spill from the target `sp+0x24` to `sp+0x20`. Use a block-scoped `s8` allocator result instead. Keep the two unused byte locals before the live type index to preserve its `sp+0x2D` location and the `0x30`-byte frame.

Simply writing `flags |= slot | 0x80000` made IDO combine the existing flags with the slot before adding the constant, unlike the target. Casting the grouped signed expression to `u32` preserves the desired grouping:

```c
s8 slot = func_800F3990_102940(arg0, alienTypes[typeIndex].unk50);
alienInstances[arg0].unk20 &= ~7;
alienInstances[arg0].unk20 |= (u32)(slot | 0x80000);
```

This produces the target order: sign-extend the slot, OR it with `0x80000`, then OR that result with the masked existing flags. Both stores to `unk20` remain. The cast is necessary for matching code generation even though it does not change the resulting bits.
